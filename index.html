09 / Performance

Mode Cycle Time Use Case

Achieving <50ms Latency

  • asyncio - Non-blocking I/O operations
  • Persistent connections - No reconnection overhead
  • Batch reads - Read 100 registers in 1 request
  • Connection pooling - Pre-established sessions
  • Edge processing - Zero cloud latency
  • Optimized TCP - Disable Nagle's algorithm

Performance Calculation

10 PLCs x 50 registers x 100ms cycle = 5,000 register reads/second
Data throughput: 5,000 x 2 bytes = ~10 KB/s (easily handled by Gigabit Ethernet)

14 / Vendor-Lock Solutions

Handling Vendor-Locked PLCs

"What if the vendor doesn't share register addresses?"

Strategy 1: Protocol Analysis

  • Passive Monitoring: Mirror port captures traffic
  • Wireshark Analysis: Identify register addresses
  • Pattern Recognition: Correlate with machine state

Strategy 2: OPC-UA Bridge

  • Many PLCs expose OPC-UA server
  • OPC-UA provides standardized tag discovery
  • No need to know internal register mapping

Strategy 3: SCADA Integration

  • Request MQTT/API export from existing SCADA
  • Database-level integration (read from historian)

Strategy 4: External I/O

  • Current transformers on motor lines
  • Proximity sensors for cycle detection

18 / Implementation

Working Implementation

Mitsubishi FX5U-32M

from pymodbus.client import ModbusTcpClient client = ModbusTcpClient('192.168.3.250') client.connect() # Read D0, D1 (Holding Registers at addr 0) rr = client.read_holding_registers(address=0, count=2) d0, d1 = rr.registers[0], rr.registers[1] # Read M0 (Coil at address 8192) rc = client.read_coils(address=8192, count=1) m0 = rc.bits[0]
